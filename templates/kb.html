High Content Security Policy (CSP)

Security Mitigation

Content Security Policy (CSP) is an added layer of security that helps to detect and mitigate certain types of attacks, including Cross-Site Scripting (XSS) and data injection attacks. These attacks are used for everything from data theft to site defacement or distribution of malware.

Recommended Directives

A basic secure policy requires loading scripts and resources only from the origin:

Content-Security-Policy: default-src 'self'; script-src 'self' https://trustedscripts.com; object-src 'none';
Server Configuration Example (Nginx)
add_header Content-Security-Policy "default-src 'self'; img-src 'self' data:; script-src 'self';" always;

Medium HTTP Strict Transport Security (HSTS)

Security Encryption

HSTS is a web security policy mechanism that helps to protect websites against man-in-the-middle attacks such as protocol downgrade attacks and cookie hijacking. It forces web browsers to access the site using HTTPS only.

Server Configuration Example (Apache)
Header always set Strict-Transport-Security "max-age=63072000; includeSubDomains; preload"

Medium Clickjacking & X-Frame-Options

Security Anti-Framing

Clickjacking is an attack that tricks a user into clicking a webpage element that is invisible or disguised as another element. This can cause users to unintentionally download malware, redirect to malicious pages, or expose sensitive details. The `X-Frame-Options` or CSP `frame-ancestors` directive mitigates this by instructing browsers not to embed the page inside a frame.

Server Configuration Example (Nginx)
add_header X-Frame-Options "SAMEORIGIN" always;

Low MIME Sniffing & X-Content-Type-Options

Best Practices Content Type

MIME sniffing is the practice of inspecting the content of a byte stream to attempt to deduce the file format of the data. If a server does not declare a correct Content-Type header, or if an attacker uploads a malicious file acting as an image, browsers might execute it as Javascript. Setting `nosniff` prevents this behavior.

Server Configuration Example (Nginx)
add_header X-Content-Type-Options "nosniff" always;

Low Server Disclosures (Server & X-Powered-By)

Information Leak Hardening

HTTP headers that disclose the exact server brand, version, and operating system (e.g. `Apache/2.4.41 (Ubuntu) PHP/7.4.3`) help malicious actors find exact known CVE vulnerabilities associated with that deployment. Disabling version headers makes exploitation harder.

Server Configuration Example (Apache)
ServerTokens ProductOnly ServerSignature Off
